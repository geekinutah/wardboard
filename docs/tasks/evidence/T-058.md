## Findings
Unmatched report rows that land on an existing assignment do not fill that assignment. `apps/server/src/import/plan.ts:372-382` treats any existing single as a reason to create a new list, and an existing list only appends a new position. Positions are filled earlier only when the printed board-group name equals the report organization (`plan.ts:92-96` and `169-180`). The organization key map can still select that board group, and the calling group can still be reused, so the existing position is never used.

Observed in the disposable worktree with board group `Ward-wide Callings` (`ward_wide`), calling group `Music`, single `Music Coordinator`, and one report row `Other Callings` / `Music` / `Music Coordinator` / `Northwood, Brielle`:

```text
[{"id":"as-coord","type":"single","positions":[{"id":"pos-coord","member":null}]},
 {"id":"new-0002","type":"list","positions":[{"id":"new-0003","member":"new-0001"}]}]
```

The original position was vacated and a second list was added. That contradicts T-058’s assignment rule (fill an existing assignment in order; append only extra list rows; do not give a single a second assignment for its first row) and SPEC.md §8: imports replace occupants while preserving the catalog, including vacant and custom positions. The same hole applies to an existing list whose positions were not consumed by the name key: those seats stay vacant and new seats are appended.

Required correction: when an unmatched row reuses a calling group, place it on the next unused position of the same-title assignment (`position.order`, then id), skipping positions already taken by an earlier row. Append only after a list’s positions are used. If the only assignment is a single and its position is already used, keep today’s new list for the extra rows. Do not create that list while the single’s position is unused. Count filled positions in `matchedPositions` / `keptPositions`, and do not mark them unfamiliar. Add a unit test for this key-map case, including a list that fills before it appends. The existing “single is not widened” case must still pass.
