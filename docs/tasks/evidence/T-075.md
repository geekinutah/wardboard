## Notes / blockers:
The contract text says a server "error" frame, but `apps/server/src/ws/channel.ts` `refuse()` sends `{ type: 'rejected', requestId, code, message }`. The client and tests follow that wire shape. `setShowNeedsApproval` treats every in-flight settings waiter as successful on one `requestId: ''` broadcast (`apps/web/src/sync/client.ts:742` and `:784`), so two overlapping calls can both resolve `{ ok: true }` before the second request is actually accepted or rejected. That is outside the single-request acceptance cases. Recorded as B-034. Risk is low. Suggested direction: settle only the oldest settings waiter per empty-requestId broadcast.
