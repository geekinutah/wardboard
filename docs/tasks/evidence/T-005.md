## Findings:
Proposal `status` NULL bypasses the check that is supposed to allow only `draft` or `accepted`. In `apps/server/src/db/migrations/001-initial.ts:83-86` the expression is `(kind = 'proposal' AND status IN ('draft', 'accepted')) OR (kind <> 'proposal' AND status IS NULL)`. SQLite treats a CHECK as satisfied when the expression is NULL, and `NULL IN ('draft', 'accepted')` is NULL, so a proposal inserted with `status` omitted is stored as NULL. Confirmed on a migrated `:memory:` database: row `pnull` (`kind=proposal`, `status=null`, `baseline_board_id=base`) inserted successfully. SPEC.md §3 and §7 require a proposal status of Draft or Accepted. Required correction: make the proposal arm false for NULL, for example `(kind = 'proposal' AND status IS NOT NULL AND status IN ('draft', 'accepted')) OR (kind <> 'proposal' AND status IS NULL)`, and add a test that NULL proposal status fails while `draft` and `accepted` still succeed.
